## 范围与通过标准

M5在M4运动、感知、融合和安全基线上建立可重复的建图、地图重载、定位与导航能力。完整数据链为：

```text
雷达和里程计契约
→ SLAM建图
→ 地图保存和重载
→ AMCL定位
→ Nav2全局规划
→ 局部控制和避障
→ 恢复行为和任务取消
```

通过标准不是软件包可发现或节点能够启动，而是固定仿真场景中的地图、定位、规划、控制、避障、取消、异常与恢复均具有可重复的自动断言、日志或rosbag证据，并且导航命令始终经过现有安全链。

## 初始接口与所有权契约

### TF所有权

- 坐标树保持`map -> odom -> base_link -> sensor_link`。
- 建图模式由`slam_toolbox`独占发布`map -> odom`。
- 定位模式由AMCL独占发布`map -> odom`。
- `ekf_filter_node`继续独占发布`odom -> base_link`。
- `robot_state_publisher`继续发布`base_link`下游静态外参。
- SLAM与AMCL不得同时作为`map -> odom`权威发布者。

### 公共接口

| 接口 | 类型/用途 | 初始契约 |
|---|---|---|
| `/scan` | `sensor_msgs/msg/LaserScan` | SLAM和代价地图的雷达输入，继续复用M3/M4 QoS与Frame |
| `/odom` | `nav_msgs/msg/Odometry` | SLAM、定位和导航的融合里程计输入 |
| `/map` | `nav_msgs/msg/OccupancyGrid` | SLAM输出或地图服务器输出；同一模式仅允许一个权威发布者 |
| `/amcl_pose` | `geometry_msgs/msg/PoseWithCovarianceStamped` | 定位结果及协方差证据 |
| `/initialpose` | `geometry_msgs/msg/PoseWithCovarianceStamped` | AMCL初始位姿输入 |
| `/goal_pose` | `geometry_msgs/msg/PoseStamped` | 人工调试入口，不代替Action验收 |
| `NavigateToPose` | `nav2_msgs/action/NavigateToPose` | 导航目标、反馈、成功、失败和取消的主要能力接口 |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 导航命令必须进入现有安全节点，不得直达控制器 |
| `/diagnostics` | `diagnostic_msgs/msg/DiagnosticArray` | SLAM、定位、导航和安全异常的统一可观测出口 |

### 模式与启动入口

- 启动文件必须显式支持`mode:=sim|real`，上层地图、定位和导航接口不感知底层模式。
- 建图与定位导航使用独立入口，避免TF和地图发布权冲突。
- `mode:=real`在实体资源未准入前不得启动实体驱动或产生硬件运动输出。
- 初步建议入口为`mapping.launch.py`和`navigation.launch.py`，最终路径在实现时冻结。

## 场景与参数准备

M5需要建立专用导航世界，至少包含封闭边界、非对称地标、走廊、转角、固定障碍物、可插入临时障碍物、多个固定目标点及不可达区域。每个测试点应冻结名称、坐标、朝向和允许误差。

场景基线已固化为`worlds/m5_navigation.sdf`和`config/m5_scenario.yaml`。世界边界为12 × 10 m，包含不对称内部墙体、两类特征地标、三个可达目标、一个四面封闭的不可达目标，以及默认不预置的临时障碍物注入契约。坐标、尺寸、可达预期和自动检查详见`docs/testing/m5_scenario_contract.md`。

机器人本体尺寸为长0.42 m、宽0.30 m。Nav2配置必须据此冻结矩形`footprint`或保守`robot_radius`，并记录膨胀半径、障碍安全距离、局部/全局代价地图分辨率、最大速度、加速度和控制频率；不得直接采用未经验证的示例参数。

## SLAM建图入口与初始质量基线

- 独立入口：`ros2 launch ai_robot_bringup mapping.launch.py mode:=sim|real`。
- `mode:=sim`复用M4安全、传感器、融合里程计和诊断链，覆盖世界为`m5_navigation.sdf`；`mode:=real`在实体驱动未准入前保持无仿真、无SLAM和无硬件输出。
- SLAM实现：`slam_toolbox/async_slam_toolbox_node`，参数固化于`config/slam_toolbox_m5.yaml`，不修改第三方文件。
- TF所有权：建图模式由`slam_toolbox`独占发布`map -> odom`，EKF继续独占`odom -> base_link`；SLAM基准Frame明确使用`base_link`。
- 输入：`/scan`、`/odom`及TF，全部使用Gazebo `/clock`时间域。
- 输出：`/map`为Reliable/TransientLocal，Frame为`map`，分辨率固定0.05 m；实测只允许一个`/map`发布者。
- 运动安全：动态测试仅发布0.35 rad/s原地旋转命令到公共`/cmd_vel`，仍经过限速和0.5秒超时停车安全节点。
- 初始局部地图阈值：宽和高均至少150格，占用栅格至少40，自由栅格至少1,000，必须保留未知区域且已知比例至少2%。首次阈值采样观察到占用56格、自由1,246格。
- 自动证据：3项静态契约测试验证模式、世界覆盖、参数和TF口径；1项launch测试实际启动Gazebo与SLAM并验证地图、TF、QoS和内容，耗时31.40秒。
- 边界：本项证明建图入口和初始局部地图有效；地图文件、SHA-256、保存和重载已在下节关闭，完整世界覆盖仍属于后续路线验收。

## 地图保存、版本摘要与重载基线

- Git地图位于`src/ai_robot_bringup/maps/m5_baseline.{yaml,pgm}`；尺寸235 × 197格，分辨率0.05 m/格，原点`[-5.93, -4.93, 0.0]`。

- `map_server.launch.py mode:=sim|real`提供独立回载入口，Nav2生命周期管理器自动配置并激活地图服务器。
- 动态回载测试验证`map` Frame、几何和三类栅格数量与Git摘要完全一致；静态测试会阻止地图文件与摘要不同步。
- 保存/回载测试暴露并修复了灰度205未知区在`free_thresh: 0.25`下被误判为空闲的问题，固定阈值为0.19。
- 详细命令、摘要与边界见`docs/testing/S1_M5_map_evidence.md`。该地图仍是局部基线，完整世界覆盖由后续路线验收关闭。

## AMCL定位与恢复基线

- 独立入口：`ros2 launch ai_robot_bringup localization.launch.py mode:=sim|real`；仿真模式启动M5场景、既有安全与融合链、地图服务器和AMCL，实体模式保持无仿真、无定位和无硬件运动输出。
- 参数固化于`config/amcl_m5.yaml`，Frame固定为`map/odom/base_link`，输入固定为`/scan`，采用差速运动及likelihood-field雷达模型，粒子范围500至2000。
- 定位入口不包含`slam_toolbox`，AMCL独占`map -> odom`，EKF继续独占`odom -> base_link`。
- 动态测试从约0.515 m平面初始偏差开始，经0.30 rad/s安全旋转后断言误差下降、协方差有效且TF存在。
- 恢复测试注入超过0.7 m的错误估计，再经公共`/initialpose`重新初始化，恢复误差小于0.25 m。
- 2项静态契约和1项实际Gazebo launch测试通过；动态测试约18.7秒。详细证据见`docs/testing/S1_M5_amcl_evidence.md`。
- 边界：结论仅覆盖当前局部地图内的偏差收敛及人工重新初始化；全局定位和绑架恢复仍需完整地图与后续路线场景验证。

## Nav2配置与生命周期基线

- 独立入口：`ros2 launch ai_robot_bringup navigation.launch.py mode:=sim|real`；仿真模式复用M5定位入口，实体模式不启动Nav2或实体驱动。
- 全局规划使用NavFn，局部控制使用DWB；控制频率15 Hz，最大线速度0.25 m/s、角速度0.70 rad/s，均低于底盘安全上限。
- 机器人轮廓冻结为保守矩形0.52 × 0.40 m；全局代价地图使用`map`及静态/障碍/膨胀层，局部代价地图使用`odom`、4 × 4 m滚动窗口及障碍/膨胀层，分辨率均为0.05 m，膨胀半径0.45 m。
- `planner_server`、`controller_server`、`behavior_server`和`bt_navigator`由独立生命周期管理器自动配置并激活。
- 实际Gazebo测试验证四个节点均为`Active`，全局/局部代价地图Frame、尺寸和分辨率符合契约。
- 运行时端点检查证明`controller_server -> /cmd_vel -> cmd_vel_safety_node -> /base_controller/cmd_vel_unstamped`，且底盘控制输入没有旁路发布者。
- 3项静态契约和1项动态launch测试通过；详细参数、命令、证据与边界见`docs/testing/S1_M5_nav2_baseline.md`。
