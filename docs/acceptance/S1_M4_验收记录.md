## 已关闭项

### 1. M4统一集成启动入口与启动顺序

- 启动入口：`ros2 launch ai_robot_bringup m4_bringup.launch.py mode:=sim|real`。
- `mode:=sim`按“公共安全/诊断层 → 仿真底盘与传感器实现 → 实体创建后加载控制器”的契约启动完整M4场景。
- `mode:=real`只启动公共安全、里程计契约和诊断节点；实体驱动尚未准入，因此保持无硬件输出的安全状态。
- 非法`mode`由launch参数`choices=['sim', 'real']`拒绝。
- 自动证据：`m4_launch_contract_test`检查模式、仿真实现选择和声明顺序；`test_bringup_launch.py`运行验证实体模式的安全节点、参数与诊断契约。

### 2. 底盘、编码器、里程计与TF集成

- 自动场景：`test_m4_motion_launch.py`通过M4统一入口启动完整仿真，不绕过`/cmd_vel`安全入口。
- 控制器：`joint_state_broadcaster`和`base_controller`均达到`active`状态。
- 接口与TF：持续收到`/joint_states`和`/odom`；验证`odom -> base_link -> sensor_link`链路存在。
- 方向与累计量：正向命令使左右轮累计量和里程计X正向增长，反向命令使三者反向变化。
- 一致性：以轮半径0.075 m换算的双轮平均位移与里程计位移绝对误差不超过0.04 m。
- 实测结果：M4运动集成launch测试1项通过，耗时13.94秒。

## 初始契约

- 坐标树保持`map -> odom -> base_link -> sensor_link`，M4不允许重复发布`odom -> base_link`。
- 仿真时间域内的融合、TF和传感器消息必须使用一致时钟，不得以墙钟替代数据时间戳。
- 上层继续使用`/cmd_vel`、`/odom`、`/scan`、`/imu/data`和`/diagnostics`，不感知`sim|real`底层差异。
- 故障注入必须可恢复且不得绕过命令超时、速度限制或底层失联保护。
