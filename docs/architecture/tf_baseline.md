# S1-M1 TF与时间基线

## 目标树

```text
map -> odom -> base_link -> sensor_link
```

实际传感器使用语义明确的子Frame，例如`laser_link`、`camera_link`和`imu_link`；`sensor_link`表示规范中的抽象占位，不要求运行时发布同名Frame。

## 发布责任

| 变换 | 类型 | 唯一发布责任 | 频率 | 时间语义 |
|---|---|---|---|---|
| `map -> odom` | 动态 | SLAM或定位组件二选一 | 由定位资源冻结，目标≥10 Hz | 位姿估计时间 |
| `odom -> base_link` | 动态 | 底盘里程计或融合节点二选一 | 目标≥20 Hz | 里程计采样/融合时间 |
| `base_link -> sensor_link` | 静态 | 机器人描述与`robot_state_publisher` | 启动时发布并保持 | 静态变换 |

同一变换禁止多个发布者同时竞争。仿真与实体必须保持相同父子关系和轴向定义，只允许标定数值、噪声和发布实现不同。

## 坐标约定

- 遵循REP-103右手坐标系：`x`前、`y`左、`z`上。
- `base_link`位于机器人基准位置；具体原点在机器人模型冻结时记录。
- 传感器Frame原点和方向来自安装/仿真模型，实体外参必须有标定来源和日期。
- Topic的`header.frame_id`必须能在目标树中解析，不使用前导`/`。

## 时钟与有效性

- sim模式统一设置`use_sim_time:=true`并使用Gazebo `/clock`。
- real模式设置`use_sim_time:=false`并使用系统ROS时钟；跨设备部署前必须定义时间同步方案。
- 动态TF时间戳对应产生数据的采样/估计时刻，不使用零时间或未来时间掩盖延迟。
- 验收至少检查树连通、单一发布者、更新频率、最大年龄和消息Frame一致性。

## 异常行为

- TF缺失、断链、过期或跳变时，依赖组件不得继续声称定位或导航有效。
- 静态外参未知时不得使用单位变换代替真实标定。
- 发生多发布者冲突或时间倒退时发布`/diagnostics` WARN/ERROR，并保存日志或rosbag证据。
